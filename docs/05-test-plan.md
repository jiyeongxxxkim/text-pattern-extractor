# 테스트 계획

- 작성일: 2026-09-18

## 1. 유닛 테스트
- 도구: Vitest (Node 런타임, D-003과 일관)
- 대상: `lib/extractAccount.js`, `lib/generateHashtags.js`, `lib/parseDate.js`
- 범위: 함수별 정상 케이스 1개 이상 + 수동 작성 엣지 케이스 5개 이상
- 실행 시점: 로컬 개발 중 및 CI(PR 생성 시)

## 2. AI 기반 엣지케이스 테스트
### 2.1 생성 단계
- 실행: `node qa/generate-cases.mjs`
- 입력: 태스크별 스펙(구현 코드 미포함)
- 출력: `qa/cases/{account,date,hashtag}.json`, 각 100개 이상, 결정적 태스크는 기대값 포함

### 2.2 실행 단계
- 실행: `node qa/run-qa.mjs`
- 방식: `lib/` 함수를 직접 호출하여 케이스 일괄 검증
- 출력: `qa/report/YYYY-MM-DD.json` (성공/실패 목록, 정답률)

### 2.3 채점 단계
- 결정적 태스크(계좌, 날짜): 기대값과 문자열 비교, AI 미개입
- 모호한 태스크(해시태그): `node qa/judge-fuzzy.mjs` 실행, 별도 컨텍스트 에이전트가 관련성 1~5점 채점, 3점 미만 실패 처리

## 3. 검증 및 개선 루프
1. 정답률 95% 미만 시 실패 케이스 로그 분석
2. `lib/` 정규식·분기 로직 수정
3. 동일 케이스셋으로 재실행, 정답률 재측정
4. 수정 이력과 정답률 변화를 CHANGELOG에 기록

## 4. E2E 테스트 (선택, M5 이후)
- 도구: Playwright
- 범위: 텍스트 입력 → 변환 버튼 클릭 → 결과 표시 → 클립보드 복사
- 도입 시점: 핵심 로직(M1~M4) 정답률 95% 달성 이후
