# 아키텍처 설계

- 작성일: 2026-09-18

## 1. 디렉토리 구조
```
src/
  lib/            # 순수 함수 (extractAccount, generateHashtags, parseDate)
  ui/             # DOM 연결 코드만 위치, 로직 미포함
tests/
  unit/           # lib 함수별 유닛테스트
qa/
  generate-cases.mjs   # AI 호출: 엣지케이스 + 기대값 생성
  judge-fuzzy.mjs      # AI 호출: 정답이 모호한 태스크(해시태그) 채점
  run-qa.mjs           # lib 함수를 직접 import해 케이스 일괄 검증
  cases/               # 생성된 케이스 JSON (gitignore 대상 원본 포함 시)
  report/              # 날짜별 QA 리포트
docs/                  # 본 설계 문서 일체
```

## 2. 설계 원칙
- 추출 로직(`lib/`)은 순수 함수로 작성하고 UI와 분리한다. QA 스크립트가 이 함수를 직접 import하여 검증하므로, 로직을 별도 언어로 재구현하지 않는다 (D-003).
- UI 계층은 `lib/`의 반환값을 표시하는 역할만 수행한다.

## 3. QA 파이프라인 데이터 흐름
```
[생성 에이전트]                     [구현 코드]                [채점]
스펙만 보고 케이스+정답 생성   →   lib/*.js 실행        →   결정적 태스크: 문자열 비교
(구현 코드 미열람)                 (케이스 미열람 상태로 작성됨)   모호한 태스크: 별도 컨텍스트의
                                                              채점 에이전트가 점수화
                                        ↓
                                qa/report/YYYY-MM-DD.json
                                (정답률, 실패 케이스 목록)
```

## 4. 역할 분리 원칙 (D-004)
- 생성 에이전트와 구현 코드 작성 시점은 서로의 산출물을 참조하지 않는다 (블라인드 검증).
- 정답이 명확한 태스크(계좌번호, 날짜)는 생성 단계에서 기대값을 함께 생성해 AI 개입 없이 문자열 비교로 채점한다 (D-005).
- 정답이 모호한 태스크(해시태그)만 별도 컨텍스트의 채점 에이전트가 점수를 매긴다.
- 동일 벤더(Anthropic) 사용에 따른 한계(모델 공통 맹점 공유 가능성)는 인지하고 있으며, 포트폴리오 기술 시 "멀티 LLM 교차검증"이 아닌 "역할 분리 기반 자동 검증"으로 정확히 표기한다.
